FOLLOW-ALONG LAB / FIRST DEPLOYMENT

Run a web app behind a Kubernetes Service.

This small manifest puts two NGINX Pods behind one internal Service. It is a practice example you can run on a local cluster before adapting the pattern to your own application.

01 / CHECK

Confirm your cluster is ready

Use a local cluster such as kind or minikube, with kubectl pointed at it. kubectl get nodes should list at least one ready node.

kubectl get nodes
kubectl config current-context
02 / DECLARE

Save this as hello-web.yaml

The Deployment keeps two Pods running. The Service uses the matching app: hello-web label to reach them.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-web
spec:
  replicas: 2
  selector:
    matchLabels:
      app: hello-web
  template:
    metadata:
      labels:
        app: hello-web
    spec:
      containers:
        - name: web
          image: nginx:stable
          ports:
            - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: hello-web
spec:
  type: ClusterIP
  selector:
    app: hello-web
  ports:
    - port: 80
      targetPort: 80
03 / VERIFY

Apply, inspect, and view the result

kubectl apply -f hello-web.yaml
kubectl rollout status deployment/hello-web
kubectl get pods -l app=hello-web
kubectl port-forward service/hello-web 8080:80

Check: while port forwarding runs, open http://127.0.0.1:8080/ to see the sample page. Stop forwarding with Ctrl+C.

TROUBLESHOOTING

Follow the labels.

If the Service has no endpoints, confirm its selector matches the Pod template’s labels.

If Pods are not ready, inspect kubectl describe pod and kubectl logs deployment/hello-web for scheduling or image errors.

For production, pin an image version or digest instead of a moving tag.
