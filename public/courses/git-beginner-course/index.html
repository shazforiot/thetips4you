FOLLOW-ALONG LAB / GIT BASICS

Build a small history you can actually inspect.

Use a throwaway folder to see how a working tree, commits, and branches fit together. These commands work with a recent Git installation on Windows, macOS, or Linux.

01 / START

Create a repository

Open a terminal in a new folder. The -b main option names the initial branch; local user.name and user.email identify your practice commits.

mkdir git-practice
cd git-practice
git init -b main
git config user.name "Your Name"
git config user.email "you@example.com"
02 / SAVE

Make your first commit

Create a file called README.md in your editor and add a sentence about what you are learning. Then stage that file and save the snapshot.

git status
git add README.md
git commit -m "Start the practice project"
git log --oneline

Check: git log --oneline should show your commit.

03 / BRANCH

Try a change without touching main

Create a branch, add a second sentence to the README, and commit it. Switch back to main and merge your work.

git switch -c feature/notes
git add README.md
git commit -m "Add learning notes"
git switch main
git merge feature/notes
git log --oneline --graph --decorate --all

Check: your new commit appears in the history on main.

WHEN SOMETHING LOOKS WRONG

Two useful checks

“Nothing to commit” means Git sees no staged change. Save the file, run git status, then stage it again.

Identity unknown means Git needs a name and email before the commit. Run the two git config commands above in this repository.
