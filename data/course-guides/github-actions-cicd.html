FOLLOW-ALONG LAB / CI PIPELINE

What happens when you push a change?

A GitHub Actions workflow can check a project automatically. This small Vite example gives you a concrete way to connect triggers, jobs, steps, and build results.

01 / TRIGGER

A push or pull request starts the run

Keep the workflow in .github/workflows/ci.yml. Configure push and pull_request for the branch you want to check.

02 / BUILD

The runner repeats your local steps

Checkout retrieves the repository, setup-node chooses a Node version, npm ci installs the lockfile versions, and npm run build checks that Vite can produce an output bundle.

03 / VERIFY

Read the run, not just the badge

Open the repository’s Actions tab. A failed build points to a specific step and log. This workflow checks the build; a separate deployment workflow publishes the site.

COMMON FAILURES

What to inspect first

npm ci fails: confirm package-lock.json is committed and matches package.json.

Build script missing: check the scripts.build entry in package.json.

Works locally only: compare the Node version and required environment variables.
